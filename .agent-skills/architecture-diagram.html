1 · Orchestrator Agent
Master coordinator. Dispatches sub-agents, assembles results, emits job status events. Never reads documents directly.
✓ Dispatch pipeline stages
✓ Return structured JSON status
✗ Read raw documents
✗ Make compliance judgments
2 · Parser Agent
Converts Docling output to clean structured nodes. Removes all noise (TOC, headers, footers, pagination). Logs everything ignored.
✓ Normalize and clean text
✓ Generate stable semantic node IDs
✓ Log all ignored items
✗ Use page number as identity
3 · Ontology Mapping Agent
Classifies each node into the universal compliance ontology. Confidence <0.70 → flagged for human review. Every call is audit-logged.
✓ Classify into ontology types
✓ Output confidence scores
✓ Flag uncertain mappings
✗ Decide compliance
4 · Semantic Alignment Agent
Matches Doc A nodes to Doc B nodes using embedding scores. Handles renamed/moved sections. Returns SAME / MODIFIED / NEW / DELETED / AMBIGUOUS.
✓ Align nodes across documents
✓ Handle renames and moves
✗ Merge nodes of different types
✗ Make compliance judgments
5 · Evidence Extraction Agent
Given a MODIFIED_NODE pair, extracts only meaningful compliance-relevant changes. Ignores whitespace, formatting, and reordered rows.
✓ Identify numeric value changes
✓ Detect status changes (PASS→FAIL)
✗ Report formatting changes
✗ Produce compliance verdicts
6 · Explanation Agent
The ONLY agent that produces free-form text. Writes 2–4 sentence explanations of findings for auditors. Never speculates or recommends remediation.
✓ Explain findings in plain English
✓ Reference standard + clause + values
✗ Recommend remediation
✗ Make compliance determinations
7 · Report Generation Agent
Assembles all findings into a structured audit report. Executive summary → critical findings → warnings → ignored changes (mandatory). Every finding has source traceability.
✓ Assemble full audit report
✓ Include ignored_changes panel
✓ Cite doc + page + clause per finding
✗ Omit any finding
Core Ontology Classes
Requirement
Normative clause from a standard (CISPR, ISO, etc.)
Observation
Recorded test result or inspection finding
Measurement
Specific numeric value with unit and frequency
Threshold
Limit line or acceptance criterion
Control
Test setup, procedure, or mitigation measure
Evidence
Certificate or supporting artifact
Deviation
Non-conformance, failure, or exceedance
Risk
Assessed risk level derived from deviations
Core Relationships (Neo4j)
Document -[:CONTAINS]→ Section
Section -[:IMPLEMENTS]→ Requirement
Observation -[:EVIDENCE_FOR]→ Requirement
Observation -[:EVALUATED_AGAINST]→ Threshold
Observation -[:RESULTS_IN]→ Deviation
Deviation -[:MITIGATED_BY]→ Control
Requirement -[:PART_OF]→ Standard
Risk -[:DERIVED_FROM]→ Deviation
