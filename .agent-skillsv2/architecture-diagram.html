A1 · Stage 7 · Ontology
Ontology Classification Agent
Triggered: keyword classifier confidence < 0.70
Classifies document nodes into the universal compliance ontology (Requirement, Measurement, Threshold, Deviation...). Always runs after deterministic keyword classifier. Output Pydantic-validated before graph write.
✓ Classify into ontology types
✓ Return confidence + review_flag
✗ Compute PASS/FAIL or margin
✗ Write to graph without schema validation
A2 · Stage 10 · Relationships
Relationship Resolution Agent
Triggered: deterministic layers A/B/C produce no match (Layer D only)
Proposes semantic relationships between compliance entities when explicit ID references are absent. All Layer D edges carry review_flag=true. Cannot bypass RelationshipValidator.
✓ Propose typed relationships
✓ Provide textual basis for proposal
✗ Write edges without RelationshipValidator
✗ Layer D edges become COMPLETED findings
A3 · Stage 13 · Alignment
Alignment Adjudication Agent
Triggered: top-2 candidate scores within 0.05 (AMBIGUOUS state)
Resolves ambiguous node alignment between Doc A and Doc B. Uses standard refs, clause IDs, and measurement values. Returns SAME_NODE, MODIFIED_NODE, or AMBIGUOUS_UNRESOLVABLE (conservative fallback: split into DELETED + NEW).
✓ Adjudicate close alignment candidates
✓ Use standard refs + clause IDs as signals
✗ Use page numbers or positions
✗ Merge nodes of different ontology_type
A4 · Stage 14 · Split/Merge
Split/Merge Alignment Agent
Triggered: SplitMergeDetector signals 1:N or N:1 pattern
Determines whether a section was split into multiple sections (SPLIT) or multiple were merged (MERGE). Prevents false-positive DELETED_NODE + NEW_NODE findings from document reorganizations.
✓ Confirm SPLIT / MERGE / NOT_SPLIT_MERGE
✓ Report missing sub-requirements
✗ Approve partial coverage without flagging
A5 · Stage 6 · Standards
Standard Version Resolver Agent
Triggered: StandardRegistryService cannot resolve version deterministically
Resolves ambiguous standard references to a known standard_id and version. Cross-version comparisons are always flagged. Never invents a standard that does not exist.
✓ Resolve version from context clues
✓ Flag cross-version comparison risk
✗ Infer version silently
✗ Invent non-existent standards
A6 · Stage 17 · Review Triage
Human Review Triage Agent
Triggered: once per job after all prior stages complete
Groups and prioritizes all flagged review items across the pipeline. Writes explanations of why each group needs human attention. Never resolves items — only organizes them.
✓ Group items by category and priority
✓ Write plain-English explanation per group
✗ Resolve review items
✗ Mark comparison COMPLETED
A7 · Stage 18 · Explanation
Explanation Agent
Triggered: after all findings finalized by rules engine
Writes 2–4 sentence professional explanations for each deterministic finding. References standard, clause, frequency, and measurement values. Never recommends remediation or makes compliance determinations.
✓ Explain WHAT changed + WHERE + WHY it matters
✗ Recommend remediation
✗ Create new findings
✗ Alter severity or result
A8 · Stage 18 · Report
Report Generation Agent
Triggered: after A7 explanations complete
Assembles the full audit report: executive summary, findings by severity, pending review items, ignored changes panel (mandatory), traceability table. Report without ignored_changes is incomplete.
✓ Assemble complete audit report
✓ Include ignored_changes panel (mandatory)
✓ Every finding cites doc+page+clause+rule_id
✗ Assign severity (comes from rules engine only)
✗ Mark FINAL with unresolved review items
01
Orchestrator is a state machine, not an LLM
ComplianceIngestionOrchestrator and ComplianceComparisonOrchestrator are Python state machines. No agent controls pipeline routing or stage transitions.
02
Deterministic-first execution
For every stage, a deterministic tool runs first. Agents are called only when deterministic confidence is insufficient. Agent output is always schema-validated before use.
03
Rules engine runs without any LLM
PASS/FAIL, margin, and severity are computed by DeterministicRulesEngine. This must function with OLLAMA_BASE_URL unset and all Claude agents offline.
04
No position-based identity
Page numbers are never used as node identifiers. Stable IDs are derived from standard_ref + clause + semantic_title_hash. This enables correct diffing across document versions.
05
Ignored changes always surfaced
Every artifact removed by NoiseFilter is logged in ignored_changes[]. No artifact disappears silently. The ignored changes panel is mandatory in every audit report.
06
Tri-layer graph separation
MetaGraph (provenance), LayoutGraph (structure), ComplianceGraph (semantics) are kept separate. TOC nodes, headers, and pagination never enter ComplianceGraph.
07
Evidence chain is mandatory
No finding reaches auditors without a complete evidence chain: Measurement → Threshold → Requirement → Standard → SourceLocation. Incomplete chains are routed to review.
08
Ontology version is immutable
Every graph node, edge, and finding is tagged with ontology_version. Changes require a version bump and migration. Breaking changes increment the major version.
09
Agent outputs are schema-validated
Every agent output is validated against a Pydantic schema before passing downstream. Schema validation failure is treated as confidence=0.0 and routed to review.
10
Every stage produces a typed artifact
No loose text passes between stages. Every inter-stage artifact conforms to a Pydantic contract defined in services/contracts/. This enables resume-from-failure and independent testing.
